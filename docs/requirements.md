# Requirements registry

The list of requirement ids that tests cite (standard 6.6). A requirement is one
testable statement about the behaviour of a named module, with the standard clause or
design decision it answers.

- Ids have the form `REQ-<AREA>-NNN`, where `AREA` is `CORE`, `DB`, `ING`, `FUND` or `OPS`
  and `NNN` is a three-digit number that is never reused.
- A test binds to a requirement with `@pytest.mark.criterion("REQ-...")`. A regression
  test also names the GitHub issue it guards with `@pytest.mark.defect(<issue>)`.
- The `lint` CI job runs `scripts/ci/traceability.py check` against this table. It fails
  when a registered requirement has no test, a test cites a `REQ-` id the table does not
  list, or a test carries a `defect` marker but no `REQ-` id. The `scope-N` and
  `global-N` labels that some ingestion and portopt-db tests carry in the same marker are
  not requirement ids: the check does not look them up here, but a `defect` marker on a
  test whose only ids are such labels still fails it.
- `module` is the repository path of the code the statement is about; for a statement
  that names several files, it is the first of them. `standard` is the clause of the
  code standard the row answers, followed, where the row guards one, by the risk of
  `docs/test-plan.md` in brackets. A cell cannot hold a `|`.
- Requirements are registered for the critical functions of `docs/test-plan.md`, for the
  items under its table that show an id, and for the traceability check and its wiring.
  Tests written before the registry were tagged only where they assert one of these
  requirements, so most tests cite no id; `CONTRIBUTING.md` records that deviation.
- Do not invent an id outside this table.
