## Project Overview

Python-only **uv workspace**, **four packages** (one shared venv):

- **`packages/portopt-core/`** (declared from the repo-root `pyproject.toml`) — Pure-Python optimization library (DB-agnostic, sklearn/skfolio-based). Dist **`portopt-core`**, import `optimizer`. **The `optimizer` package lives at `packages/portopt-core/optimizer/`, NOT at the repo root** (src-layout move; `[tool.setuptools.packages.find] where = ["packages/portopt-core"]`).
- **`ingestion/`** — Headless **ingestion daemon**. APScheduler in-process, no HTTP API. Fetches market / fundamental / macro data into PostgreSQL on a schedule. Entrypoint `ingestion/app/worker.py`; manual runs via `ingestion/app/cli.py`. Dist **`portopt`**, import `app`.
- **`packages/portopt-db/`** — Shared **DB layer** (import `portopt_db`): SQLAlchemy `Base` + all models + all repositories + `DatabaseManager`/`RepositoryBase` + the single Alembic tree. Dist **`portopt-db`** (internal; consumed by both `ingestion` and `fund`).
- **`fund/`** — **LIVE** deepagents/langgraph bridge (Phases 0–9 code complete). *The LLM chooses, the optimizer computes.* Dist **`portopt-fund`**, import `fund` (src-layout `fund/src/fund/`). Entrypoints: `fund` CLI, `fund-worker` daemon, `fund-tui`.

**Boundary (guarded, load-bearing)**: `ingestion/` and `portopt-db/` do **not** import `optimizer`; `portopt-db/` carries no sklearn/skfolio stack. `optimizer` (`portopt-core`) does **not** import `portopt_db`. The daemon **does** ship `scikit-learn` (scipy transitively): yfinance's price-repair path (`repair=True`) imports `sklearn.cluster.DBSCAN`, so without it ~22% of tickers return empty history and get dropped. sklearn here is a data-layer dep, not optimization. With a single shared venv there is no install isolation — static import-scan tests are the **sole** enforcement: `ingestion/tests/unit/hygiene/test_no_optimizer_import.py`, `packages/portopt-db/tests/test_no_optimizer_import.py`, root `tests/test_no_portopt_db_import.py`. The `fund/` bridge adds a second axis: `fund` **may** import `optimizer` + `portopt_db` (the only member that may), but `deepagents`/`langgraph` live only in `fund/` — guarded by `fund/tests/unit/hygiene/test_no_ingestion_import.py` (fund ⊬ `app`) plus `test_no_agent_stack_import.py` in both `ingestion` and `packages/portopt-db` (neither imports `deepagents`/`langgraph`/`fund`).

Supporting dirs: `tests/` (library suite, mirrors `optimizer/` + `tests/scheduler/`), `ingestion/tests/` (SQLite in-memory), `packages/portopt-db/tests/` (SQLite in-memory), `fund/tests/` (SQLite in-memory + `integration` marker for live-Postgres round-trips), `scheduler/` (shell wrappers over the CLI).

**No frontend, no docs site, no `examples/`/`research/`/`cli/`, no HTTP API** — deleted in the strip (branch `refactor/strip-to-ingestion-pipeline`). Any leftover reference (a route, `TestClient`, `uvicorn`, `app.main`, `/api/v1/`) is dead — delete it, don't revive the dependency.

## Build & Run Commands

uv workspace — `uv sync` resolves all four members into one venv. Run tools per-package with `uv run --package <name>` (`portopt-core`, `portopt`, `portopt-db`, `portopt-fund`). Install through uv only: `ingestion` and `fund` reach their siblings (`portopt-db`, `portopt-core`) through `[tool.uv.sources]`, which pip ignores — a bare `pip install` of either would look those unpublished names up on PyPI. Only `portopt-core` and `portopt-db` (no sibling deps) are safe to pip-install on their own: `pip install -e .` from the repo root (the root `pyproject.toml` declares the `portopt-core` dist; `packages/portopt-core/optimizer/` is only its source tree, with no `pyproject.toml` beside it) and `pip install -e packages/portopt-db`.

uv sync --all-packages --all-extras

# Member suites run FROM THE MEMBER DIRECTORY (as CI does). `--package` only picks the

# root `testpaths = ["tests"]`, i.e. the optimizer library suite, whatever `--package` says.

# Shared DB layer (package portopt-db)

## Optimizer Library conventions

Every module: **frozen `@dataclass` config** + **factory function** + **`str, Enum` types**. Configs hold only primitives/enums/nested frozen dataclasses (serialisable). Non-serialisable objects (estimator instances, numpy arrays, callables) are factory `**kwargs`. Strict and consistent across all modules.

All transformers follow sklearn `BaseEstimator + TransformerMixin` and compose in `sklearn.pipeline.Pipeline`. `build_portfolio_pipeline()` (in `pre_selection/`) flattens pre-selection + optimiser steps so `get_params()` exposes nested params (`"optimizer__l2_coef"`, `"drop_correlated__threshold"`).

**Library is composable primitives, not a fixed end-to-end runner** — there is no `pipeline/` module and no `run_full_pipeline`. Opinionated, DB-connected orchestration (FX, delisting, universe/factor selection, rebalancing decisions, persistence) belongs to the `fund/` bridge, keeping `optimizer` DB-agnostic.

**18 submodules.** Module flow: `prices → preprocessing → pre_selection → moments → views → optimization → validation → tuning → rebalancing`. Plus `factors/`, `synthetic/`, `scoring/`, `universe/`, `distance/`, `cluster/`, `uncertainty_set/`, `linear_model/`, `online/`, `fx/`. The `optimization` module ships **fifteen optimizer builders** (config + `build_*`): mean-risk (+ regime-blended, robust), HRP, HERC, NCO, Schur-complementary, risk-budgeting, max-diversification, DR-CVaR, stacking, benchmark-tracker, and three naive baselines (equal-weighted, inverse-volatility, random).

Per-submodule detail (configs, presets, factories, shape contracts, exact estimator/factor/screen inventories) lives in each submodule's source and docstrings.

### Key conventions

- `prices_to_returns()` runs **outside** the pipeline (changes data semantics); pipelines operate on return DataFrames only
- Views use `tuple[str, ...]` in configs (hashable); factories convert to `list` for skfolio
- View configs embed `MomentEstimationConfig` for their inner prior (keeps configs serialisable)
- The fitted prior attribute is `return_distribution_` (not `prior_model_`): `mu`, `covariance`, `returns`, `sample_weight`, `cholesky`
- For `BenchmarkTracker`, benchmark returns are passed as `y` in `fit(X, y)`
- `build_portfolio_pipeline(optimizer, pre_selection_config=None, sector_mapping=None, expiration_dates=None, outlier_protection_mask=None)` (in `pre_selection/`) composes pre-selection + optimiser into one flat sklearn `Pipeline`; `sector_mapping` is injected as a plain `dict[str, str]`, not queried from the database

### Cross-cutting gotchas (skfolio 1.0)

- **Linear returns only**: pipelines/estimators consume linear (simple) returns as `X`. Use `prices_to_returns()` — do NOT pass log returns
- **`shuffle=False` in CV**: temporal CV must preserve order. `KFold(shuffle=True)` / `train_test_split(shuffle=True)` break causality and silently leak future data
- **Metadata routing**: call `sklearn.set_config(enable_metadata_routing=True)` BEFORE `.set_fit_request(...)`. Required for `ImpliedCovariance.implied_vol`, `BenchmarkTracker.y`, etc.
- **`TimeSeriesFactorModel.fit(X, factors=...)`**: `X` asset returns, `factors` factor returns (keyword-only in 1.0). Wrapped in Black-Litterman, views reference factor names (not asset names)
- **`BenchmarkTracker.fit(X, y)`**: `y` is the benchmark return series; the Config carries no benchmark field — pass at fit time
- **Variance estimators store `variance_` (1-D), NOT `covariance_` (2-D)** — `EmpiricalVariance`/`EWVariance`/`RegimeAdjustedEWVariance` are NOT interchangeable with covariance estimators inside priors needing a full matrix
- **`Pipeline` is rejected by `online_predict` / `OnlineGridSearch`** — skfolio routes `partial_fit` through a single estimator. Apply pre-selection to `X` upstream. **Online instances are not thread-safe — one wrapper per thread**
- **Walk-forward CV cannot vary constraints per fold** — regime-dependent sector bands are fixed for a whole run; a backtest is single-regime, not per-rebalance
- **EW estimators take `half_life`, not `alpha`** (1.0 breaking change; `alpha` raises `TypeError`)

## Ingestion / DB / Scheduler (summary)

Full tables and internals live in the `portopt_db` models and the ingestion service/scheduler source. Load-bearing points:

- **DB layer (`portopt-db`)**: single schema + connection manager + Alembic tree (**head `b8d0f2a4c6e1`**, runs from `packages/portopt-db`). Pure structural extraction, no sklearn/optimizer import (guarded). `background_jobs` *model* lives here but `BackgroundJobRepository` *behavior* stays in `ingestion/app/repositories/jobs/`. Coverage floor ≥ 90% (blended statement+branch)
- **Daemon layering**: Scheduler/CLI → Services → Repositories → Models, `_shared/` per layer. Models + most repos live in `portopt_db`; ingestion keeps only the `jobs` repo. No HTTP API. Sync SQLAlchemy sessions — everything opens its own via `database_manager.get_session`. PostgreSQL 16 on port **54320**. **Do not reintroduce `optimizer` as an ingestion dep**
- **Scheduler**: APScheduler in-process in `worker.py`, `SQLAlchemyJobStore`. **Seven jobs**: `daily_pipeline` (daily 07:00), `midday_news` (daily 14:00), `universe_build` (**Sat** 02:00), `weekly_refetch` (**Sat** 03:00), `weekly_market_wide` (**Sat** 04:00), `fred_monthly` (1st 08:00), `orphan_reaper` (interval). `universe_build` runs **before** `weekly_refetch` (every step iterates `instruments`, a stale universe caps yfinance). `daily_pipeline` runs `run_universe_step()` first when `instruments` has no active rows (`_universe_is_empty`, fresh install), and never fails on it. One public step function each in `scheduler.py` — **add new work as a step, not a CLI-only branch**
- **Gotcha — sync steps need an explicit heartbeat**: only the heartbeat thread stamps `last_heartbeat_at`. A sync step outliving `SCHEDULER_ORPHAN_HEARTBEAT_TIMEOUT_SECONDS` (300s) gets falsely reaped and flips to `failed` mid-run. Wrap work in `scheduler._heartbeat()`
- **Gotcha — reaper is a heartbeat lease** (NOT host-scoped): `reconcile_orphans` fails any active `(pending|running)` row whose `last_heartbeat_at` is NULL or older than the lease TTL — there is **no** `worker_host`/`worker_pid` reap predicate (those columns are observability-only; the removed host-scoped design is stale). Run exactly one daemon per DB
- **Gotcha — JSONB in test-covered models**: use `JSON().with_variant(JSONB, "postgresql")` so SQLite tests can create the table
- **Gotcha — transient-error detection** (`infrastructure/retry.py`): case-sensitive substring match. `"Too Many Requests"` trips the breaker; `"too many requests"` does not
- **Cron weekday gotcha**: APScheduler `from_crontab` numbers days `0=Mon..6=Sun`. Use weekday names (`sat`); a bare `0` fires Monday
- **Gotcha — a venue lives in five tables**: the universe admits a listing only if its Yahoo exchange code is in `_CODE_TO_CONFIG_NAME`, `_CODE_TO_REGION` (ETF region query) and `_EXCHANGE_PREF` (canonical tiebreak) of `yfinance_source`, its exchange name is in `UniverseBuilderConfig.yahoo_suffix_map`, and a MIC is in `EXCHANGE_NAME_TO_MIC` (without one the truncated-history guard is silently lost). FX needs no table: the floor resolves whatever currencies the data carries through `{MAJOR}USD=X`. `test_universe_venues.py` keeps the five in step. ETFs are classified from their names (`classify_instrument`): bond/multi-asset/commodity markers first, equity as the fallback, leveraged/inverse and crypto/currency/volatility funds rejected; `add-instrument --pin` corrects a mislabel
- **Trading 212 is a tradability overlay, not the universe source**: when keyed, `t212_annotate` sets `instruments.t212_ticker` and the tri-state `instruments.is_t212_tradeable` (NULL = not evaluated, true = in the broker catalogue, false = matched and absent; every active row is judged, mandate-pinned ones included, and only a `manual` pin keeps its `t212_ticker` and ISIN untouched; an empty or ISIN-less catalogue flags nothing and clears no stored ticker). `UniverseRepository.get_t212_tradeable_tickers()` is the allowlist hook for a broker-executable run: `None` means the overlay never evaluated anything, so keep the full universe; `[]` means it ran and matched nothing. ISINs exist only for suffix-less (US) symbols by design (the Business Insider scrape answers a venue-suffixed symbol with a secondary line's ISIN): `t212_annotate` stores the ISIN it looks up (`set_isin_if_missing`), and `backfill_isin_from_profiles` never copies a profile ISIN onto a venue-suffixed symbol
- **Gotcha — ticker news falls back to Yahoo search**: Yahoo retired the `/xhr/ncp` route behind `Ticker.news`, and yfinance 1.7.0 reports its 404 page as `YFDataException("*** YAHOO! FINANCE IS CURRENTLY DOWN! ***")` although Yahoo is up. `fetch_yahoo_news` treats that error like an empty feed and uses `yf.Search`; `TickerFeedHealth` skips the dead feed after 5 failures in a row and probes it again every 30 minutes. Rate-limit and network errors still propagate to the retry and breaker logic: the search fallback runs under the shared rate limiter, breaker and request tally (`fetch_ticker_news`), so a 429 or 5xx from it counts as a lost request, not as a `news:` error string. Upstream's GraphQL fix (yfinance PR #3018) sits on its `dev` branch and is unreleased as of 1.7.0, so the bump that carries it needs no code change

Key env vars: `DATABASE_URL`, `TRADING_212_API_KEY` + `TRADING_212_SECRET_KEY` (either absent ⇒ the `t212_annotate` step skips without claiming a slot; `universe_build` itself needs neither), `FRED_API_KEY`, `METRICS_PORT` (9000), `YFINANCE_FETCH_WORKERS` (1-16, default 4), `NEWS_RETENTION_DAYS` (365; the weekly refetch prunes older `ticker_news` rows in bounded batches, 0 disables). The full list + `SCHEDULER_*` crons are documented in `ingestion/.env.example` and `app/config.py`.

## Fund bridge (`fund/`, LIVE)

The bridge where an LLM makes decisions and delegates numerics to `optimizer`, persisting to Postgres via `portopt_db`. Only member that may import both `optimizer` and `portopt_db`; `deepagents`/`langgraph` are confined here. Model path: a **switchable provider registry** selected by `LLM_PROVIDER` over any LangChain chat model — ten providers (`ollama`/`openai`/`openrouter`/`anthropic`/`google`/`groq`/`nvidia`/`huggingface` [cloud-only]/`aws` [Bedrock]/`microsoft` [Azure]); env-free default stays DeepSeek on Ollama Cloud via `langchain-ollama`. Non-default provider SDKs are opt-in extras (`uv sync --package portopt-fund --extra <provider>`, or `--extra all-llm`; `openrouter`/`microsoft` ride on `--extra openai`, `ollama` needs none); builders lazy-import so a bare `import fund.agents.model` pulls no provider SDK. Durable checkpointer + store on a **dedicated `langgraph` Postgres schema** (`langgraph-checkpoint-postgres` over `psycopg`). Design record: `docs/ARCHITECTURE.md`, `docs/DECISIONS.md` and `docs/adr/`.

- **Gotcha — `fund.audit` loads `persistence` (langgraph) lazily**: `fund/audit/__init__.py` resolves `LangGraphPersistence`/`setup_langgraph` through a PEP 562 `__getattr__`, so importing the package or any repository submodule stays agent-stack-free; only touching those two names (or `fund.audit.persistence`) pulls langgraph. Keep audit repos **lazy** anyway (the `observe` pattern) as defence in depth so a module's bare import stays agent-stack-free (needed to keep `worker.py`/`scheduler.py` importable without the agent stack). Guard: `fund/tests/unit/hygiene/test_audit_submodule_imports.py` (fresh-interpreter probe per repository submodule)
- **Gotcha — test UUID/SQLite affinity**: `portopt_db/base.py` compiles `postgresql.UUID` as `CHAR(32)` on SQLite. Without it the declared `UUID` type name gets NUMERIC affinity, a hex id that parses as a number (all digits, or one `e`) is stored as REAL, and the UUID result processor crashes — random `uuid4` keys hit it a few times per full run. Keep that hook; declare UUID columns as `postgresql.UUID` or `Uuid`. Guard: `packages/portopt-db/tests/test_uuid_sqlite_affinity.py`
- **Gotcha — committing repos + shared session**: `FundJobRepository` commits; the shared SAVEPOINT `db_session` leaks commits across the session-scoped engine — use a private function-scoped engine (`job_session`) in tests, and `synchronize_session=False` on the reaper UPDATE. The fund worker's job slot is a **heartbeat lease**, mirroring the ingestion reaper
- **Theory-consultation protocol**: the `THEORY_CONSULTATION_PROTOCOL` is wired onto all agent prompts and the profiler (openwiki-first). The `openwiki` MCP server backs it — if it fails to connect, note that rather than assuming the capability is absent
- **TUI (`fund-tui`, `fund.tui.app:ShellApp`)**: an 8-view Textual oversight cockpit (Posture · Deliberation · Decisions · Mandate · Audit · **Performance** · **Ask** · Daily brief) in `VIEW_SPECS`/`_VIEW_CLASSES` (`views.py`). Reads go through `fund.observe` (agent-stack-free); every mutation routes through `fund.actions.apply_action` behind a confirm, dispatched on `@work(thread=True)` workers in `app.py`. **Ask** (`tui/ask.py` — model-free classify/resolve/retrieve; stdlib + `observe` only) answers queries with a **read-only deep agent** (`fund/agents/ask_agent.py`, built lazily on a worker: fund-data tools over `fund.observe`, a read-only staged copy of the docs and source at `/docs` and `/code`, deepagents' automatic compaction, one checkpointer thread per scope) and routes decision-verb actions through the confirm/audit path, disambiguating an ambiguous target first (`pending_action` across turns) — never on a guess. **Performance** reads the shipped tracker only through `observe.performance_summary`/`observe.holdings_summary`. Help overlay on `?`/`F1`; status is **dot + label**, never colour alone
- **Gotcha — the Ask agent is contained, and its history is deleted in three places**: the agent sees only `stage_ask_workspace`'s allowlisted text copy (never the checkout or `/run/secrets`, where the container mounts every provider key), `read_only_permissions` denies each write at the tool level, the backend has no shell, and a turn is capped by `FUND_ASK_MAX_STEPS` (25 rounds) and `FUND_ASK_TIMEOUT_SECONDS` (180 s). The adviser reads an exact transcript kept per scope (a portfolio id, or `fund`) as LangGraph Store items under `("ask","history",<scope>)` (`fund/tui/ask_history.py`, bounded to 500 messages); the agent's own memory is the checkpointer thread `ask:<scope>`. `/clear` in the Ask box, behind a confirm, deletes the Store items, the thread (`delete_thread`) **and** the scope's scratch dir (compaction offloads the evicted history there as markdown with portfolio data); it is refused while a question is pending or another clear runs (`_ask_pending`, `_ask_clearing`, with `_ask_lock` serialising the agent thread). Also: the delegated helper subagent is capped at 4 model calls (the helper graph carries its own 9999 limit), the tools open every Postgres transaction `READ ONLY`, control characters are stripped and a message is cut at 20,000 characters before it is saved or shown (`fund/tui/safe_text.py`), an answer is saved with the scope it was asked in even if the header portfolio changes meanwhile, and error notes are shown but never saved. the `ask:` thread is never pruned (a Postgres `keep_latest` prune dropped the conversation from the latest checkpoint and wiped the agent's memory; only `/clear` removes it); the offloaded history files and exported markdown files survive until `/clear`, and exports are never deleted by it. In a conversation about one portfolio the data tools refuse every other portfolio (the fund-wide conversation may read all), and every tool result (holdings, mandate, audit, run transcripts) is sent to the configured model provider. The saved transcript is read, written and deleted on one ordered background thread (`ShellApp._ask_io`), never on the event loop
- **Gotcha — keep `fund.tui.*` import-light**: `import fund.tui.app` must pull **no** `deepagents`/`langgraph`/model **and no `optimizer`/`skfolio`** at module scope — the model is built lazily in the Ask worker, and the Performance/Posture reads reach the tracker only via `fund.observe` (which lazy-imports it inside the function body). `tui/ask.py` imports **only stdlib + `fund.observe`** (no Textual). Guards: `test_import_app_is_light_and_needs_no_keys` (`test_tui.py`), `test_import_fund_tui_ask_is_light` (`test_ask.py`), and the agent-stack-free `test_import_fund_observe_is_agent_stack_free`

- **Eligible universe (`PortfolioMandate.eligible_tickers`)**: a hard per-portfolio allowlist of Yahoo tickers; empty means unrestricted (the pre-feature behaviour) and the benchmark is **not** auto-eligible. `fund.tools.eligibility.resolve_mandate_eligibility` resolves it once per run into `Eligibility(allowed, barred)` bound to `RunContext.eligible` (on run, resume and the adviser edit path, always from the *current* mandate). It is enforced in the weighting tools: `list_universe` returns only the allowed set (with `instrument_type` and `asset_class`, not the market-cap ranking that buries every ETF), `universe_filter` / `estimate_moments` / `optimize_portfolio` refuse an outside ticker, `risk_check` records a `not_eligible` violation, and `place_orders` and the adviser edit refuse; the read-only data tools (`get_prices`, `get_regime_stats`) stay unrestricted. Bar reasons: `no_instrument`, `delisted`, `not_priced`, `not_t212_tradeable`, `esg:<gics sector>`, `esg_unclassified`. Opt-in **broker scope** `PortfolioMandate.tradeable_only` (default False, JSON-only, no migration) composes with it (both must hold): the resolver also bars any name whose `instruments.is_t212_tradeable` is an explicit False (`not_t212_tradeable`) via `UniverseRepository.get_t212_untradeable_tickers`. It is tri-state: NULL on a row is not evaluated and is **not** barred, nothing evaluated at all (`None`) leaves the universe whole and surfaces an `Eligibility.notes` caveat in the PM seed and as a mandate-save warning (never a silent empty universe), and an allowlisted name the overlay could not judge (no ISIN to match, so every active row is NULL) is kept but named in the same two places (`UniverseRepository.get_t212_unevaluated_tickers`), and all-False is an honest empty universe. With no allowlist it still engages as a refusal list over the whole universe (`Eligibility.has_allowlist` False: `list_universe` drops the False rows in SQL, the tools refuse them, the ESG stored-sector screen for funds is unchanged). Set it with `fund mandate set --eligible T ... | --clear-eligible`, `--tradeable-only / --no-tradeable-only`, or the TUI Mandate view's "eligible tickers" field and "Tradeable on Trading 212 only" box; both route through `fund.actions.apply_action`, which warns once about tickers without a priced instrument and syncs the pins. Put an instrument the Screener never returns into the universe first with `portopt add-instrument <TICKER> --asset-class <class> --pin` (ingestion; no job slot; an ETF needs an explicit `--asset-class`: `equity`, `fixed_income`, `multi_asset` or `commodity`)
- **Gotcha — `fund.tools.eligibility` is not import-light**: it reaches the optimizer through `fund.tools.universe`, so import it lazily inside a function and never from `fund.observe` or `fund.tui` (`fund.actions` and `fund.agents.graph` do exactly that)
- **Gotcha — pins keep hand-added instruments in the universe**: `pinned_instruments` (keyed by ticker text, one row per `(ticker, source)`; sources are `manual` and `mandate:<portfolio_id>`) keeps an instrument out of the weekly delisting sweep, stops the Screener upsert from rewriting its classification and, for a `manual` pin, stops `t212_annotate` from clearing or overwriting its `t212_ticker` and ISIN (a mandate pin is still evaluated for `is_t212_tradeable`). A pin protects only the row that carries the symbol (its `ticker` equals the symbol, or no canonical row exists), so a delisted sibling row that shares the `yfinance_ticker` is not revived, and `replace_pins` revives only tickers a save newly claims and never a row with a recorded `delisting_return`. A mandate save replaces the portfolio's `mandate:<id>` pins through `PinnedInstrumentRepository.replace_pins` inside `apply_action`. Code that calls `MandateRepository.upsert` directly, or an idempotent action that replays, bypasses that sync
- **Gotcha — ETF ESG look-through fails closed**: under ESG exclusions an ETF is judged by its latest `etf_sector_weights` snapshot against the client's `look_through_tolerance` (default 0.0, strict). Commodity and government / inflation-linked bond ETFs pass (a fund whose latest `etf_asset_classes.stock_pct` on or before the decision bar exceeds the tolerance is looked through instead); every other fund needs a snapshot dated on or before the decision bar and no older than `esg_sector_weights_max_age_days` (180, env `FUND_ESG_SECTOR_WEIGHTS_MAX_AGE_DAYS`) whose weights are finite and sum to 1 within 0.05, otherwise it is barred `esg_unclassified`. The unreported remainder `1 - total` counts as possible exposure to an excluded sector the snapshot omits, so at the strict default a 0.96 total bars the fund. Ingestion fetches the fund data for every ETF, but most corporate and aggregate bond ETFs still have no sector data and stay barred, by design. Under an allowlist the stored-sector screen (`constraint_set_breaches(funds_by_look_through=True)`) leaves ETFs to the resolver, because a fund has no sector and the screen would bar all of them
